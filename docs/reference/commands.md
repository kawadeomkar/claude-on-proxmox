# Commands

Every entry point is a [`just`](https://github.com/casey/just) recipe, run from anywhere in the checkout.
Each one uses the project's Python environment, so the tool versions locked in `uv.lock` are the ones that
run, and each one that runs Ansible keeps a log of the whole run in `.logs/` ([Run logs](../guides/runs.md#run-logs)).
`just` prints the same list in the terminal, and `just help <recipe>` one recipe's options.

There are few recipes, and each does the whole of its job by default: `just deploy` everything from the
template to the editor's window, `just login` all three sign-ins, `just lint` every linter, `just test` every test.
An option or a word narrows one to a part of it - `just deploy alpha --only configure`, `just test
integration` - and the indented rows below are each recipe's options and words. Options go after the
recipe's name, before or after its words; `just help deploy` lists `deploy`'s. Anything a recipe does not
take - an unknown option, a stage it has not got, a name outside its characters - is refused before
anything runs. The `make` targets of earlier versions are mapped in
[Upgrading](../guides/upgrading.md#make-became-just).

The words a recipe takes, and how they are checked:

- **VM names**, after `deploy`, `login`, `list` and `destroy`, and one after `code`. Each starts with a letter
  or a digit and holds only letters, digits and `. _ - ,`. Without names, `deploy`, `deploy --only
  provision` and `destroy` act on `agent-warehouse-default`, `code` refuses to run, and the commands that
  read VMs or configure them again act on every VM this project created; see
  [Naming and multiple VMs](../guides/vms.md#naming-and-multiple-vms). `just deploy configure` asks whether
  the stage or a VM so named was meant, and without a terminal runs nothing: a stage is given with `--only`.
- **`--project`**, for `just code` only: one repository folder in the VM's projects directory.
- **`--session`**, for `just code` only: one of this machine's Claude Code sessions, by its ID - lowercase
  hex in groups of 8-4-4-4-12, as `/resume` lists it.
- **A role or a variable**, one after `settings`: a role's name (`tailscale`), one of its variables
  (`tailscale_ssh`), or a setting of `local.yml` or `vault.yml` (`vm_cores`), in lowercase letters, digits and
  `_`. Without one, `just settings` shows the roles and its options, and `--all` lists every setting.
- **`--value`**, for `just settings` beside one setting's name: the value to write into `local.yml`, as
  free text but for a control character. It reaches the recipe as one argument, run by nothing, and is
  refused unless the setting's type takes it; an expression (`{{ }}`) and a secret are refused. **`--reset`**,
  beside one setting's name instead, puts it back to its default: its line out of `local.yml`. An empty
  `--value` is no value: `--reset` is the way back to a default.
- **`--tags`** narrows configuration to some roles, and beside VM names means `--only configure`
  ([Re-running one part of it](../guides/vms.md#re-running-one-part-of-it)); **`--role`** narrows `just
  test` to some roles' scenarios. Both are checked against the role names.

Settings that are not options are exported, or given before the recipe's name, as `NAME=value`:
`ANSIBLE_ARGS` passes anything else to `ansible-playbook` (`ANSIBLE_ARGS='-f 30' just deploy --only
provision`), `LOG_DIR` moves the run logs or, empty, turns them off, and `PYTHON` names the project's
environment where `python3` is not it.

### Use

| Recipe | What it does |
|---|---|
| `just init` | Set up this checkout, then ask for what a first deploy needs |
| &emsp;`--address ADDRESS` | The Proxmox host's address, for its hosts.yml |
| &emsp;`--host ON` | Set up another host of this checkout, by its name (just host lists them); a value with a dot or a colon is taken for --address through 2.x |
| &emsp;`--token-user TOKEN_USER` | The API token's user, when it is not ansible@pve |
| &emsp;`--token-id TOKEN_ID` | The API token's ID, the part after its user's !, when it is not ansible |
| &emsp;`--token-secret-file TOKEN_SECRET_FILE` | A file holding the token's secret (or AGENT_WAREHOUSE_TOKEN_SECRET in the environment; never on the command line) |
| &emsp;`--github-user GITHUB_USER` | The GitHub account whose repositories are cloned |
| &emsp;`--storage STORAGE` | The storage for VM disks, for local.yml: written when the token can use it there |
| &emsp;`--bridge BRIDGE` | The bridge the template is built on, for local.yml (before the template exists) |
| &emsp;`--tailscale TAILSCALE` | Answers init's VPN question: on, each VM joins your tailnet; off, none - a VPN of yours that routes the LAN, or none at all (vpn in local.yml) |
| &emsp;`--no-prompt` | Ask nothing, even at a terminal |
| `just install` | Install the locked Python packages and the Galaxy collections: into your virtualenv, or this checkout's own |
| &emsp;`--lock` | Update uv.lock after editing a pin in pyproject.toml, installing nothing (uv from PATH) |
| `just vault` | Encrypt the vault, or edit it once it is encrypted |
| &emsp;`--host ON` | That host's own vault, which holds its token, rather than the shared one (just host lists them) |
| `just deploy [<name>...]` | Create, configure and sign in the VM(s), then open them in your editor |
| &emsp;`--only STAGE` | Run one stage and nothing after it: template (the cloud-init template, if missing), provision (create and start), configure (every tagged VM, unless named) or ssh-config (refresh the SSH aliases; without names, also prune those of VMs that are gone) |
| &emsp;`--check` | Dry-run configuration: ansible-playbook --check --diff (every tagged VM, unless named) |
| &emsp;`--host ON` | Run against this host rather than the current one (just host lists them) |
| &emsp;`-t, --tags ROLES` | Configure only these roles, comma-separated: beside VM names it means --only configure (just deploy alpha --tags claude_code) |
| &emsp;`--start` | Start a VM this run would leave stopped (proxmox_vm_start_existing) |
| &emsp;`--cores CORES` | Each new VM's vCPU cores, in place of the vm_cores setting |
| &emsp;`--memory MEMORY` | Each new VM's memory: MiB, or 16G, in place of the vm_memory_mb setting |
| &emsp;`--disk DISK` | Each new VM's root disk, as 64G or 1T, in place of the vm_disk_size setting |
| &emsp;`--repos REPOS` | Only these of your GitHub repositories on each VM named, comma-separated, in place of the github_projects setting: kept for that VM, and added to by a later --repos |
| &emsp;`<name>` | The VMs; none means agent-warehouse-default, or every VM this project created for --only configure, --check and --only ssh-config |
| `just code <name>` | Open a VM in your editor, VS Code by default, with Claude on the VM and this machine's recent Claude sessions copied there |
| &emsp;`--project PROJECT` | Open one project folder on the VM rather than the whole projects directory |
| &emsp;`--editor IDE` | Open it in this editor for this run, rather than the one the editor setting names: vscode or zed |
| &emsp;`--host ON` | Run against this host rather than the current one (just host lists them) |
| &emsp;`--session SESSION` | Continue one of this machine's Claude Code sessions there, by its ID as /resume lists it: its checkout brought to the session's pushed commit, ready for claude --resume |
| &emsp;`<name>` | The one VM to open |
| `just login [<name>...]` | Sign the VM(s) in to Claude, GitHub and Tailscale, or report how each is signed in |
| &emsp;`--host ON` | Run against this host rather than the current one (just host lists them) |
| &emsp;`--only SIGN_IN` | One sign-in: claude (by the browser, then Remote Control), github (the device flow, then the private repositories) or tailscale (its web login) |
| &emsp;`<name>` | The VMs to sign in, one after another; none reports every VM this project created |
| `just status [<name>...]` | What every VM this project created is doing, and what needs doing next, read without changing anything |
| &emsp;`--host ON` | Run against this host rather than the current one (just host lists them) |
| &emsp;`--only ONLY` | Only these sections, comma-separated: vms storage capacity access sign-ins system work; vms, storage and capacity read only the Proxmox API, never a VM |
| &emsp;`--json` | The report as JSON, alone on standard output, with the same exit code |
| &emsp;`<name>` | Only these VMs; none reads every VM this project created |
| `just settings [<name>]` | Each setting's value and where it was set, for a role, a variable or all of them; --value sets one in local.yml, --reset puts it back |
| &emsp;`--all` | Every setting of local.yml, and which secrets of vault.yml are set |
| &emsp;`--changed` | Only what local.yml or vault.yml changes from the defaults; alone, all of it |
| &emsp;`--json` | The report as JSON, alone on standard output |
| &emsp;`--host ON` | That host's values rather than the current host's; beside --value or --reset, its own local.yml is the one changed |
| &emsp;`--reset` | Put the one setting named back to its default: its line out of local.yml, its example's back |
| &emsp;`--value VALUE` | Set the one setting named to this value, in local.yml (never a secret: just vault; an empty value is none: --reset) |
| &emsp;`<name>` | A role (tailscale) or one variable or setting (tailscale_ssh); none shows how to use this |
| `just destroy [<name>...]` | Save the VM(s)' own Claude sessions here, release them from Claude, GitHub and Tailscale, then delete them |
| &emsp;`--confirm CONFIRM` | Delete without asking, these VMs only: the same names as given, comma-separated |
| &emsp;`--host ON` | Run against this host rather than the current one (just host lists them) |
| &emsp;`<name>` | The VMs; none means agent-warehouse-default |
| `just host [<name>]` | List the hosts, or make one the current host, which every command runs against unless --host names another |
| &emsp;`--json` | The list as JSON, alone on standard output |
| &emsp;`--remove` | Delete the host's folder in hosts/, after you type its name: its VMs and their SSH aliases stay |
| &emsp;`--for VMS` | With --json: the VMs a run would name, comma-separated, to say which host it would reach |
| &emsp;`--host ON` | With --json: the host a run would be given, to say which host it would reach |
| &emsp;`<name>` | The host to make the current one: every command runs against it from now on |
| `just logs` | List the run logs in .logs/, newest first |
| `just mcp` | Let Claude Code sessions in any project run these commands, through an MCP server |
| &emsp;`--any-branch` | Let the server run this checkout on any branch, or with tracked changes; without it, main with no tracked change only |
| &emsp;`--attended SCREEN` | Whether someone is at this machine's screen for the sign-ins: 1, as for Claude Desktop, or 0; unset, the server decides per session |
| &emsp;`--browser BROWSER` | What opens the sign-in pages for the runs it starts, when the default does not (BROWSER) |
| &emsp;`--project-dir PROJECT_DIR` | Register it for this one project's folder only (Claude Code's local scope), not for every project |
| &emsp;`--remove` | Take the server out of Claude Code again |
| &emsp;`--show` | Print the command, and an entry for Claude Desktop, and register nothing |
| &emsp;`--vault-password-file VAULT_PASSWORD_FILE` | Where the vault's password is, when it is not this checkout's .vault_pass |

### Develop

| Recipe | What it does |
|---|---|
| `just lint [<part>...]` | Every linter: the lock, YAML, Ansible, Python, the justfile, playbook syntax, pre-commit hooks |
| &emsp;`--all-hooks` | hooks: run every pre-commit hook, the ones lint's other parts cover too |
| &emsp;`<part>` | lock (uv.lock against pyproject.toml), yaml (yamllint --strict), ansible (ansible-lint, production profile), python (ruff check and format --check), just (just --fmt --check), syntax (--syntax-check on every playbook), hooks (the pre-commit hooks the others do not cover) |
| `just test [<part>...]` | Lint, then every test: unit and Molecule (the local quality gate) |
| &emsp;`--role ROLES` | Only these roles' scenarios, comma-separated: on its own it means the role part (just test --role common,claude_code) |
| &emsp;`--shard SHARD` | Only the I-th of N shards of the unit tests, each group of tests whole, as CI splits them: on its own it means the unit part (just test unit --shard 2/3) |
| &emsp;`--jobs JOBS` | Run the Molecule scenarios this many at a time, the longest first, each one's whole output in a log of its own and a line as each ends; one at a time without it, as their images share one disk (just test molecule --jobs 4) |
| &emsp;`<part>` | unit (pytest over tests/unit/, a worker per CPU, no network), molecule (every Molecule scenario: role, integration, provision), role (the roles' own scenarios), integration (the full configure playbook against a Docker container), provision (provision.yml and discover.yml against a fake Proxmox API) |
| `just docs [<part>]` | Regenerate the wiki's reference pages from the files they describe |
| &emsp;`<part>` | serve (the wiki as a site at http://127.0.0.1:8000, rebuilt as you save) or build (the site in site/, failing on a broken link or anchor) |
| `just vagrant [<part>]` | End-to-end test of configure.yml on a VirtualBox VM |
| &emsp;`<part>` | destroy: destroy the Vagrant test VM |
| `just clean [<part>]` | Remove caches, the run logs and the built site (never your Python environment) |
| &emsp;`<part>` | logs: delete only the run logs in LOG_DIR; env: delete only this checkout's own environment and collections, which just install makes again |
