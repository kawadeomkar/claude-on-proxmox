# Settings

Everything you can set lives in two git-ignored files that `make init` copies from their examples:
`inventory/group_vars/all/local.yml` for settings and `inventory/group_vars/all/vault.yml`, encrypted,
for secrets. Set only what differs from the default, so that a default this project changes later
still reaches you.

## Variable layering

```
roles/*/defaults/main.yml                 role defaults, role-prefixed names
inventory/group_vars/all/defaults.yml     project defaults + wiring of vm_user, github_username, … into role vars   (committed)
inventory/group_vars/all/local.yml        your overrides                                                            (git-ignored)
inventory/group_vars/all/vault.yml        secrets as vault_* variables                                              (git-ignored, encrypted)
inventory/hosts.yml                       the Proxmox host's address, nothing else                                  (git-ignored)
```

Files in `group_vars/all/` load alphabetically, so `defaults` < `local` < `vault`.

Most settings are short names that `defaults.yml` wires into a role's own variable, so you set
`claude_remote_control` rather than `claude_code_remote_control`; the table says which role variable
each one sets. A role variable can be set directly too, and each role's page lists them all:
[Roles](roles/README.md). A setting that is not in these tables is internal; changing it is
[Architecture § 6](../architecture/variables.md)'s business.

## Every setting

The tables below are generated from `local.yml.example` and `vault.yml.example`: their comments are
the descriptions, and the defaults come from `defaults.yml` and the roles' `defaults/main.yml`.
"computed" means the default is worked out at run time from other values.
