# Make targets

Every entry point is a `make` target, run from the repository root. Each one uses the project's
virtualenv, so the tool versions locked in `uv.lock` are the ones that run, and each one
that runs Ansible keeps a log of the whole run in `.logs/` ([Run logs](../guides/runs.md#run-logs)).
`make help` prints the same list in the terminal.

Two values are typed on the `make` line, and both are checked before a shell sees them:

- `VM_NAME` - the VM or VMs to act on, comma-separated. Without it, `deploy`, `provision` and
  `destroy` act on `claude-on-proxmox-default`, `code` refuses to run, `template` has no use for it,
  and the targets that act on VMs act on every VM this project created; see
  [Naming and multiple VMs](../guides/vms.md#naming-and-multiple-vms).
- `PROJECT` - for `make code` only, one repository folder in the VM's projects directory.

Three more tune a run: `TAGS` narrows `configure` and `check` to one role
([Re-running one part of it](../guides/vms.md#re-running-one-part-of-it)), `ANSIBLE_ARGS` passes
anything else to `ansible-playbook` (`ANSIBLE_ARGS="-e proxmox_vm_start_existing=true"`), and
`LOG_DIR` moves the run logs or, empty, turns them off.

### Setup

| Target | What it does |
|---|---|
| `make venv` | Create the virtualenv and sync it to uv.lock (uv from PATH) |
| `make lock` | Update uv.lock after editing pyproject.toml |
| `make deps` | Install Ansible Galaxy collections |
| `make init` | One-time local setup: venv, collections, local config from examples, pre-commit hooks |
| `make vault-encrypt` | Encrypt inventory/group_vars/all/vault.yml with ansible-vault |
| `make vault-edit` | Edit the encrypted vault file |
| `make logs` | List the run logs, newest first (in LOG_DIR, default .logs/) |
| `make logs-clean` | Delete every run log in LOG_DIR |

### Run books

| Target | What it does |
|---|---|
| `make template` | Build the cloud-init VM template on the Proxmox host (once) |
| `make provision` | Create and start VM(s): make provision VM_NAME=alpha,beta (default: claude-on-proxmox-default) |
| `make list` | Show the VMs this project created, and their addresses (all, unless VM_NAME) |
| `make configure` | Configure the VM(s): packages, tools, Claude Code, GitHub projects (every tagged VM, unless VM_NAME) |
| `make deploy` | Everything, for VM_NAME only: template (if missing), provision, configure, sign in to Claude, GitHub and Tailscale, open VS Code (default: claude-on-proxmox-default) |
| `make destroy` | Release the VM(s) from Claude, GitHub and Tailscale, then delete them (default: claude-on-proxmox-default) |
| `make claude-login` | Sign Claude Code in on the VM(s) in VM_NAME, one after another, and start Remote Control; without VM_NAME, report every VM |
| `make github-login` | Sign gh in to GitHub on the VM(s) in VM_NAME by the device flow, one after another, then clone private repositories; without VM_NAME, report every VM |
| `make tailscale-login` | Sign the VM(s) in VM_NAME in to Tailscale by its web login, one after another; without VM_NAME, report every VM |
| `make check` | Dry-run configure against real hosts (--check --diff; every tagged VM, unless VM_NAME) |
| `make ssh-config` | Refresh the SSH alias of every VM this project created (all, unless VM_NAME; fleet-wide also prunes) |
| `make code` | Open a VM in VS Code with a Claude terminal, or one project on it: make code VM_NAME=alpha [PROJECT=&lt;repo&gt;] |
