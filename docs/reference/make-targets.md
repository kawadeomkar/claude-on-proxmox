# Make targets

Every entry point is a `make` target, run from the repository root. Each one uses the project's
virtualenv, so the tool versions locked in `uv.lock` are the ones that run, and each one
that runs Ansible keeps a log of the whole run in `.logs/` ([Run logs](../guides/runs.md#run-logs)).
`make help` prints the same list in the terminal.

There are few targets, and each does the whole of its job by default: `make deploy` everything from the
template to VS Code, `make login` all three sign-ins, `make lint` every linter, `make test` every test.
`TYPE=` narrows one to a single part of it - `make deploy TYPE=configure`, `make test TYPE=integration` -
and the parts each target takes are the indented rows below. Anything else, or a `TYPE` given to a target
that takes none, is refused before anything runs, and so is a `TYPE` written as a word after the target
(`make deploy configure` would otherwise create a VM named `configure`). A target an earlier version
had, such as `make configure`, `make claude-login` or `make molecule`, stops with the command that
replaced it ([Upgrading](../guides/upgrading.md#the-make-targets-an-earlier-version-had)).

Two values are typed on the `make` line, and both are checked before a shell sees them:

- `VM_NAME` - the VM or VMs to act on, comma-separated. Without it, `deploy`, `deploy TYPE=provision`
  and `destroy` act on `claude-on-proxmox-default`, `code` refuses to run, `deploy TYPE=template` has no
  use for it, and the commands that read VMs or configure them again act on every VM this project
  created. Every target that takes it also takes the names after the target, so `make deploy alpha beta`
  is `make deploy VM_NAME=alpha,beta`; see [Naming and multiple VMs](../guides/vms.md#naming-and-multiple-vms).
- `PROJECT` - for `make code` only, one repository folder in the VM's projects directory.

More tune a run: `TAGS` narrows configuration to some roles, and beside VM names means
`TYPE=configure` ([Re-running one part of it](../guides/vms.md#re-running-one-part-of-it)); `ROLE` narrows `make test`
to some roles' scenarios, and on its own means `TYPE=role`; both are checked against the role names.
`ANSIBLE_ARGS` passes anything else to `ansible-playbook` (`ANSIBLE_ARGS="-e proxmox_vm_start_existing=true"`),
and `LOG_DIR` moves the run logs or, empty, turns them off.

### Use

| Target | What it does |
|---|---|
| `make init` | Set up this checkout, then ask for what a first deploy needs |
| &emsp;`HOST=<address>` | The Proxmox host's address, for inventory/hosts.yml |
| &emsp;`TOKEN_USER=<user@realm>` | The API token's user, when it is not ansible@pve |
| &emsp;`TOKEN_NAME=<name>` | The API token's name, when it is not ansible |
| &emsp;`TOKEN_SECRET_FILE=<file>` | A file holding the token's secret (or CLAUDE_ON_PROXMOX_TOKEN_SECRET in the environment; never on the command line) |
| &emsp;`GITHUB_USER=<login>` | The GitHub account whose repositories are cloned |
| &emsp;`TAILSCALE=on` | Each VM joins your tailnet, the default: writes tailscale_enabled: true in local.yml |
| &emsp;`TAILSCALE=off` | No Tailscale, for a setup without a Tailscale account: tailscale_enabled: false |
| &emsp;`PROMPT=no` | Ask nothing, even at a terminal |
| `make install` | Install the locked Python packages and the Galaxy collections into your environment |
| &emsp;`TYPE=lock` | Update uv.lock after editing a pin in pyproject.toml, installing nothing (uv from PATH) |
| `make vault` | Encrypt the vault, or edit it once it is encrypted |
| `make deploy [<name>...]` | Create, configure and sign in the VM(s), then open VS Code |
| &emsp;`TYPE=template` | Build the cloud-init VM template on the Proxmox host, if it does not exist yet |
| &emsp;`TYPE=provision` | Create and start the VM(s), and nothing after |
| &emsp;`TYPE=configure` | Configure VMs that exist: packages, tools, Claude Code, GitHub projects, Tailscale (every tagged VM, unless named) |
| &emsp;`TYPE=check` | Dry-run configure against the VMs (--check --diff; every tagged VM, unless named) |
| &emsp;`TYPE=ssh-config` | Refresh the SSH aliases of the VMs this project created; without names, also prune those of VMs that are gone |
| &emsp;`TAGS=<role>,...` | Configure only these roles: beside VM names as TYPE=configure, else with TYPE=configure or check (make deploy alpha TAGS=claude_code) |
| `make code <name>` | Open a VM in VS Code with a Claude terminal |
| &emsp;`PROJECT=<repo>` | Open one project folder on the VM rather than the whole projects directory |
| `make login [<name>...]` | Sign the VM(s) in to Claude, GitHub and Tailscale, or report how each is signed in |
| &emsp;`TYPE=claude` | Sign Claude Code in by the browser, then start Remote Control |
| &emsp;`TYPE=github` | Sign gh in to GitHub by the device flow, then clone the private repositories |
| &emsp;`TYPE=tailscale` | Join Tailscale by its web login |
| `make list [<name>...]` | Show the VMs this project created, and their addresses |
| `make destroy [<name>...]` | Release the VM(s) from Claude, GitHub and Tailscale, then delete them |
| `make logs` | List the run logs in .logs/, newest first |

### Develop

| Target | What it does |
|---|---|
| `make lint` | Every linter: the lock, YAML, Ansible, Python, playbook syntax, pre-commit hooks |
| &emsp;`TYPE=lock` | Check uv.lock against pyproject.toml |
| &emsp;`TYPE=yaml` | yamllint --strict |
| &emsp;`TYPE=ansible` | ansible-lint, production profile |
| &emsp;`TYPE=python` | ruff check and ruff format --check |
| &emsp;`TYPE=syntax` | ansible-playbook --syntax-check on every playbook |
| &emsp;`TYPE=hooks` | The pre-commit hooks the others do not cover (SKIP= on the line runs every hook) |
| `make test` | Lint, then every test: unit and Molecule (the local quality gate) |
| &emsp;`TYPE=unit` | pytest over tests/unit/: the filters, the github_repos module, the playbooks against stand-ins, the guards and the wiki (no network) |
| &emsp;`TYPE=molecule` | Every Molecule (Docker) scenario: each role's, then the configure and provision playbooks' |
| &emsp;`TYPE=role` | The roles' own scenarios: every role, or ROLE=&lt;role&gt;,... (make test ROLE=common,claude_code) |
| &emsp;`TYPE=integration` | The full configure playbook against a Docker container |
| &emsp;`TYPE=provision` | provision.yml and discover.yml against a fake Proxmox API |
| `make docs` | Regenerate the wiki's reference pages from the files they describe |
| &emsp;`TYPE=serve` | Serve the wiki as a site at http://127.0.0.1:8000, rebuilt as you save |
| &emsp;`TYPE=build` | Build the wiki as a site in site/, failing on a broken link or anchor |
| `make vagrant` | End-to-end test of configure.yml on a VirtualBox VM |
| &emsp;`TYPE=destroy` | Destroy the Vagrant test VM |
| `make clean` | Remove caches, the run logs and the built site (never your Python environment) |
| &emsp;`TYPE=logs` | Delete only the run logs in LOG_DIR |
